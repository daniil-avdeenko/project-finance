# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |

## Reporting a Vulnerability

Если вы нашли уязвимость, пожалуйста, **не открывайте публичный issue**.

Используйте **GitHub Security Advisories**:

https://github.com/daniil-avdeenko/project-finance/security/advisories/new

В сообщении укажите:

- версию или коммит, где воспроизводится уязвимость;
- пошаговый сценарий воспроизведения;
- ожидаемое и фактическое поведение;
- потенциальное влияние (утечка данных, эскалация привилегий, DoS и т.п.).

## Response SLA

- Подтверждение получения: **7 дней**.
- Первичная оценка: **14 дней**.
- Исправление (если применимо): **30 дней** с момента подтверждения.
- Публичное раскрытие деталей - по согласованию, после выхода исправления.

## Scope

**В скоупе:**

- Flask-приложение (https://projectfin.com.ru) - аутентификация, авторизация, обработка входных данных, HTML-рендеринг, CSRF, rate limiting.
- Публичный REST API `/api/v1/*` - включая rate limit и раскрытие данных.
- Интеграции: Google Sheets (credentials), Telegram Bot API (webhook secret), ЦБ РФ (парсинг).
- Инфраструктура развёртывания - конфигурация Nginx, TLS, Docker-сети.

**Вне скоупа:**

- Уязвимости в сторонних сервисах (Telegram, Google, ЦБ РФ) - сообщайте в upstream.
- Уязвимости в зависимостях - сообщайте в соответствующие репозитории; дублирующий advisory сюда приветствуется, чтобы отслеживать влияние на проект.
- Social engineering, фишинг, физический доступ.

## Known Limitations

- **`GIGACHAT_VERIFY_SSL=false` в production** - временный обход проверки сертификатов GigaChat; для полной проверки нужны сертификаты Минцифры (Russian Trusted Sub CA), установка на сервер - в бэклоге. Влияет только на исходящие запросы к LLM, не на входящие. Риск MITM ограничен сетевым периметром между NL-сервером и `api.giga.chat`; данные - демонстрационные.
- **Rate limit на логин - Redis-backed, с fallback на memory.** Если Redis недоступен на старте - Limiter откатывается на `memory://` (лимиты в памяти одного воркера). Если Redis падает **в рантайме** - `swallow_errors=True` пропускает запросы без ограничений до восстановления: `/login` остаётся доступным, но защита от брутфорса временно отключается. Redis - единая точка для кэша и rate limit.
- **CSP с `'unsafe-inline'`** для `style-src` и `script-src` - осознанное решение, чтобы работали Bootstrap и inline-скрипты в шаблонах. Ослабляет защиту от XSS по сравнению со strict CSP с nonce.
- **HSTS отсутствует** - заголовок `Strict-Transport-Security` не выставлен. Планируется добавить отдельно (в бэклоге).
- **Бэкапы PostgreSQL** - пока вручную; автоматические `pg_dump` с ротацией в S3-совместимое хранилище в бэклоге.
- **Демонстрационные учётные данные `admin/admin`** - только для публичного демо на https://projectfin.com.ru.
